### 版本号机制

`.ai_pdf_runtime/.ver`存三个源文件 sha256拼接后的前16位。JS层每次调用先算哈希，不一致才重新解包覆盖。**所以 core.py改动必须重跑 gen_package.py，否则运行时还是旧代码。**

## 1.总体调用链

```
AI调 ai_pdf:make_pdf
 → ai_pdf.js校验参数、算源文件哈希
 →解包到 .ai_pdf_runtime/
 → hiddenExec: python3 core.py build {json}
 → md2typst.convert(md) Markdown → Typst片段
 → make_cfg(a)参数 → #let cfg = (...)
 →拼: cfg + theme2.typ + cover + header + body + extra_typst
 →写临时 .typ
 → typst compile --root / tmp.typ out.pdf
 →校验 %PDF-文件头 +用 fitz读页数
 →返回 {success, output, bytes, pages, theme, palette, engine}
 → AI再用 render_pdf_preview渲染成 PNG，read_file(direct_image=true)自己看
```

|段|失败时的表现|
|---|---|
|md2typst|`error_type=markdown`|
|拼接/cfg|`error_type=syntax`或 `bad_unit`|
|typst compile|`error_type`按 stderr关键词分类|
|产物校验|`output is not a PDF`|

### 2.4 cmd_build的8步

1. `sys.path.insert(0, HERE)`后 `import md2typst`（同目录）
2. `read_md(a)`取 Markdown
3.检查 theme2.typ存在，读进来
4. `md2typst.convert(md)` → body片段；异常 → `markdown conversion failed`
5.按序拼：`make_cfg(a)` + `theme` +换行 + `make_cover`（仅 cover真）+页眉 + body + `extra_typst`
6. `tempfile.mkstemp`写临时 .typ，然后 `typst compile --root / tmp.typ out`
7.校验：returncode、文件存在、大小 >0、前5字节是 `%PDF-`
8. `fitz`读页数（失败不影响成败，pages返回 null）

|font_body|body-font|覆盖主题|

### 2.6 make_cover：全绝对定位

封面是单独一页 `#page(margin:0pt, header: none, footer: none)[...]`，内部靠 `place`定三段：

|段|定位|内容|
|---|---|---|
|标题组|`place(top+left, dx:24mm, dy:74mm)`|kicker胶囊 →标题32pt →46mm渐变条 →副标题|
|装饰卡片|`place(bottom+left, dx:24mm, dy:-50mm)`|`cover_cards`最多3个，`grid(columns:(1fr,)*n, gutter:8pt)`|
|底部信息|`place(bottom+left, dx:24mm, dy:-22mm)`|细线 + `cover_meta`|

背景是160度渐变 +左侧10mm竖向色条。`cover_cards`用 `|`分隔卡片、`::`分隔标题与说明。

**dy从42mm调到74mm是为了让标题落在视觉中线**，改之前封面中部空一大块。

### 2.7 classify的9条规则

|关键词|error_type|hint|
|---|---|---|
|maximum function call depth|internal_recursion|主题内部函数递归（工具 bug）|
|unknown variable|undefined_symbol|组件名或 Typst函数不存在|
|invalid number suffix|bad_unit|边距 mm、字号 pt、行距 em|
|unexpected argument|bad_argument|多半是 extra_typst给了不支持的键|
|unclosed delimiter|syntax|优先删 extra_typst|
|expected|syntax|同上|
|not found|missing_resource|图片用绝对路径，字体用 Noto Serif CJK SC|
|pandoc|markdown|检查未闭合的 :::或代码块|
|typst binary|engine|先跑 selfcheck|

都没命中 → `unknown`，提示先删 extra_typst重试。

## 3. md2typst.py（2880行）

**Markdown → Typst片段的唯一实现**。AI永远不写 Typst，正确性全压在这一层。

### 3.1主链路3步

1. `preprocess(md)`：先把"简体写法"修成 pandoc认的语法
2. `md_to_ast(md)`：`pandoc -t json`出 AST
3. `R().render(ast)`：遍历 AST拼 Typst，`out()`取结果

`convert(md)`是把这三步串起来的对外函数，异常统一抛 `TypstError`。

### 3.2 preprocess干的四件事

|动作|原因|
|---|---|
|`- [x]` → `☒`，`- [ ]` → `☐`|pandoc的 task_lists要求 `]`后有空格，无空格就不识别，会渲染成 `• [x]文字`双标记|
|`#标题` → `# 标题`|缺空格的标题 pandoc不当标题，会原样输出|
|`::: callout warn标题` → `::: {.callout .warn data-title="标题"}`|pandoc的 fenced div属性行只接受英文标识符，中文会破坏语法|
|裸词变体识别|`warn注意`这类粘连写法，剥出 `warn`当 class、`注意`当标题|

变体词白名单：`note info success warn danger quote primary soft neutral`。

正则两条：`_RE_OPEN`匹配 `^:::\s*([A-Za-z][\w-]*)`，`_RE_KV`匹配 `key=value`。

### 3.3 R.blk：Block类型分发

|AST类型|输出|
|---|---|
|Para / Plain|内联展开 +空行|
|Header|`=` × level +空格 +内联|
|BulletList / OrderedList|`_list(items, "-")` / `("+")`|
|BlockQuote|`#blockquote[...]`|
|CodeBlock|`_code(code, lang)`，lang决定高亮|
|Table|`_table(c)`|
|HorizontalRule|`#hr()`|
|Div|`_div(attr, inner)` ←组件入口|
|LineBlock|逐行输出|
|RawBlock|html走 `_raw_html`，其余按代码块|

### 3.4 R._div：组件路由表

这是**组件能力的唯一真源**，加新组件只改这里 +theme2.typ。

|div class|调用|说明|
|---|---|---|
|`kpi`|`_pairs(inner,"kpirow")`|每行 `值\|说明`|
|`badges`|`_badges(inner)`|每行 `标签\|变体`|
|`callout`|`#callout(kind:·, title:·)[...]`|kind取第二个 class，title取 `title`或 `data-title`|
|`cards*`|`_cards(inner, cls, kvs,后缀)`|**前缀匹配**，`cards2`=2列、`cards3`=3列|
|`compare`|`_compare(inner)`|左右各一组 `###标题`|
|`progress` / `rating`|`_numbered(inner, name)`|每行 `名称\|数值`|
|`chart`|`_chart(inner)`|每行 `标签\|数值`|
|`timeline`|`_timeline(inner)`|每行 `时间\|说明`|
|`steps`|`_steps(inner)`|每行一个步骤|
|`defs`|`_defs(inner)`|每行 `术语\|定义`|
|`pagebreak`|`#pagebreak()`|空内容|
|`toc`|`#sectiontoc()`|空内容|
|`no-break` / `nobreak`|`#block(breakable: false)[...]`|防孤行|
|其他|原样渲染内部|不报错，降级成普通内容|

`name.startswith("cards")`是关键，早期写成 `== "cards"`导致 `cards2`不分栏。

### 3.5内部 helper

|函数|作用|坑|
|---|---|---|
|`_lines(blocks)`|把块统一成 `(kind, inlines, level)`三元组|三种块形态归一，后面所有组件解析都靠它|
|`_split_pipe(inlines)`|按 `\|`切字段，每段 `_trim`|不裁空白会导致字段带首尾空格|
|`_pairs(blocks, wrapper)`|两列 → grid|kpi专用|
|`_cards(blocks, cls, kvs, cols)`|卡片网格|cols优先取 `kvs["cols"]`，其次 class后缀|
|`_list(items, marker)`|列表|**task item不画圆点**，改 `#block(inset: (left:1.2em, y:2.5pt))`|
|`_table(c)`|表格|列宽按内容算，数字列右对齐|
|`_aligns(colspecs, ncol)`|对齐方式|`AlignRight` → `right`|
|`_raw_html(txt)`|HTML透传|只处理已知标签，其余转义|
|`ins(nodes)` / `ino(n)`|内联展开|`Emph`→`_`，`Strong`→`*`，`Code`→反引号|

**内联转义**：`_ESC`表处理 `# $ * _ \` | @ < >`。任何用户文字进 Typst前必须过 `esc()`。

### 4.2 show rules

用 `#show`接管标题、代码块、表格、引用、列表标记。改版式优先改这里，不要在 md2typst里拼样式。

### 4.3三条铁律

1. **不要给内置函数起同名封装**。`#let pagebreak() = pagebreak()`会解析到自己，一调用就 `maximum function call depth`爆栈，整份 PDF报废。要封装就换名。
2. **块间距要显式归零**。`#set block(spacing:0pt)`必须写在文件前部，否则 `#block`默认 above取全局1.2em，两层嵌套叠加就是40-60px的空隙（h2下划线飞出去的元凶）。
3. **标题下划线用 stroke画，不要用 border**。`block(stroke: (bottom: ...))`配 `spacing:0pt`才贴得紧。

## 8. 数学公式（texmath.py，340 行）

**AI 写 LaTeX，工具转 Typst。** 这是整包最绕的一层，因为 Typst 数学语法和 LaTeX 差得远。

### 8.1 为什么需要它

Typst 原生数学极强，但语法完全不同：

| LaTeX | Typst |
|---|---|
| `\frac{a}{b}` | `frac(a, b)` |
| `\sqrt{a}` / `\sqrt[3]{a}` | `sqrt(a)` / `root(3, a)` |
| `\sum_{i=1}^{n}` | `sum_(i=1)^n` |
| `\int_0^1` | `integral_0^1` |
| `\begin{pmatrix}...\end{pmatrix}` | `mat(delim: "(", ...)` |
| `\text{速度}` | `"速度"` |
| `\mathrm{d}x` | `dif x` |

直接塞 `$...$` 会报 `unknown variable: mc`。所以必须转。

### 8.2 五个关键坑（都是实测踩出来的）

| 坑 | 现象 | 修法 |
|---|---|---|
| **连续字母** | `mc^2` → `unknown variable: mc`；`\pi ab` 同理 | 主循环里把裸字母串拆成 `m c`，但 `dif/thin/med` 白名单保留 |
| **符号粘连** | `2\pi\sqrt{..}` → `2pisqrt(...)` | 希腊字母/运算符输出后补尾随空格 |
| **函数前粘连** | `a\cos\theta` → `acos theta` | `_pre_fn` 在已知函数名前插空格 |
| **Typst 关键字被误拆** | `mat(delim: ...)` → `mat(de lim: ...)` | GUARD 表先把 `delim/block/cases/...` 整词换成占位符，处理完再还原 |
| **上下标带空格** | `lim _(n` 报错 | `_tight_scripts` 把 ` _` / ` ^` 压成 `_` / `^` |

### 8.3 处理顺序（`convert` 返回前）

```
_fix_scripts   →  ^{...} 换 ^(...)，_{...} 换 _(...)，最多迭代4轮
_pre_fn        →  已知函数名前插空格（带 GUARD 保护）
_sep_symbols   →  希腊字母/运算符后补空格
_tight_scripts →  压掉 _ 和 ^ 前面的空格
```

**顺序不能换**：先拆字母、再补空格、最后收紧，反了会互相破坏。

### 8.4 失败降级

`md2typst._math()` 用 try/except 包住：转换抛异常就原样返回 LaTeX 原文，让 typst 报清晰的语法错，而不是吞掉。

## 10. mermaid.py（615 行）

**Mermaid flowchart → SVG，零依赖。** 因为 mmdc 要 Chromium（装不了）、mermaid-py 丢中文，最后自己写。

### 10.1 四个阶段

| 函数 | 作用 |
|---|---|
| `parse(src)` | 文本 → Graph（nodes + edges + direction）|
| `_layout(g)` | 算 rank，分配 x/y/w/h，返回画布尺寸 |
| `_routes(g)` | 算每条边的路径点，返回 Route（head/tail/color/label）|
| `to_svg(g, path)` | 拼 SVG 写盘 |

### 10.2 解析要点

- 节点形状按**长度降序**匹配：`[(圆柱)]` 必须先于 `[矩形]`，否则 `[[` 被 `[` 抢先
- 边类型按长度降序：`-->|标签|` 先于 `-->`，`-- 文字 -->` 先于 `---`
- `_find_edges()` 从每个位置尝试所有边模式，取**最长匹配**，避免 `--` 被切成 `-` + `-`
- `_split_chain()` 用 `prev` 状态支持连续链 `A-->B-->C-->D`

### 10.3 分层：DFS 去环 + Kahn

回环边（如 `D --> A`）会让所有节点入度非零，Kahn 进不去。所以：

1. **先 DFS 三色标记找出回边**（GREY 遇到 GREY = 回边）
2. 回边**不参与入度计算**
3. Kahn 拓扑求最长路径分层
4. 仍未访问的节点按前驱 rank + 1 兜底

### 10.4 路由：三段正交

```
TD 模式：源底部 → 垂直下 spread → 水平到目标 x → 垂直进目标顶部
LR 模式：源右侧 → 水平右 spread → 垂直到目标 y → 水平进目标左侧
```

**三段拆成 head + tail 的原因**：head 是「水平分支段」，按边标签语义上色（是=绿、否=橙）；tail 是「进目标段」，统一灰色带箭头。这样标签色只染水平段，跟主流工具一致。

### 10.5 特殊情况

| 情况 | 处理 |
|---|---|
| 多入边汇合 | 各边独立垂直下 → 收到目标中轴 → 短竖进目标（漏斗形）|
| 回环 / 向上边 | 从源底部出 → 下绕 22pt → 推到画布最右侧 +34 → 上到目标 y → 进目标右侧 |
| 回环需要画布留白 | TD 模式下 `W = max_span + MARGIN*2 + 46` |

### 10.6 形状与语义色

| shape | 来源语法 | 填充/描边 |
|---|---|---|
| `rect` | `[x]` | 蓝底蓝框 |
| `round` | `(x)` | 蓝底蓝框，rx=12 |
| `dia` | `{x}` | 橙底橙框，polygon |
| `start`/`end` | `([x])` | 蓝底，胶囊（rx=h/2）|
| `circle` | `((x))` | 蓝底圆 |
| `cyl` | `[(x)]` | 紫底，数据库圆柱 |
| `sub` | `[[x]]` | 蓝底，两侧竖线 |
| `asym` | `>x]` | 蓝底，左斜梯形 |

**不做形状推断**：`[x]` 就是矩形，起始/结束必须显式写 `([x])`。早期按「入度为 0 就画胶囊」推断，把所有普通起点都变成了胶囊。

### 10.7 Typst 嵌入

`md2typst._mermaid()` 把 Mermaid 代码块转成 SVG 存到临时文件，再输出：

```typst

  #align(center)[#image("/tmp/mmd_xxx.svg", width: 468.0pt)]

```

**变异点**：`width: 100%%` 里的 `%)` 会被 Python `%` 格式化当格式符，必须写 `100%%`，否则 `ValueError: unsupported format character`。

### 10.8 已知限制

- 不支持 subgraph

## 11. 几何图形与圆角组件（theme2.typ 可直接搬）

全部用 Typst 原生图元，**零依赖、矢量、可缩放**。完整可跑样张：
`展示/几何图形样张.typ`（+ `.pdf`，单页 210×316.9mm）。

### 11.1 关键区别：哪些图元能内嵌文字

| 图元 | 语法 | 能否内嵌文字 |
|---|---|---|
| `rect` | `rect(width:, height:, radius:)` | ✅ 它是 `box` 的简写，直接包内容 |
| `circle` | `circle(radius:)` | ❌ 纯图元，要外包 box |
| `ellipse` | `ellipse(width:, height:)` | ❌ 同上 |
| `polygon` | `polygon((x,y), (x,y), ...)` | ❌ 同上 |
| `path` | `path((x,y), ..., closed: true)` | ❌ 同上 |
| `curve` | `curve(move((x,y)), line((x,y)), ...)` | ❌ 纯线条 |

**结论**：要「形状里装文字」，统一用下面这个模式，不要试图给 `circle` 塞内容：

```typst
box(width: 78pt, height: 40pt, radius: 50%,
    align(center + horizon, text(...)[内容]))
```

`radius: 50%` 是关键：宽高相等时是正圆/正椭圆，宽高不等时自动成胶囊。

### 11.2 五个可直接复制的配方

### 11.3 环形进度（唯一需要算坐标的）

Typst **没有** `curve.arc()`。只能把弧拆成 72 段折线，肉眼已看不出棱角。

```typst
#let ring(pct, d: 64pt) = {
  let r = d / 2 - 2.5pt
  let steps = 72
  let seg = int(calc.round(pct / 100.0 * float(steps)))
  let pt(i) = {
    let a = (float(i) / steps) * 2 * calc.pi - calc.pi / 2
    (r + r * calc.cos(a) + 2.5pt, r + r * calc.sin(a) + 2.5pt)
  }
  box(width: d, height: d, {
    // 底环：整圈
    place(top + left, curve(
      stroke: 5pt + rgb("#DDE2EA"),
      curve.move(pt(0)),
      ..range(1, steps + 1).map(i => curve.line(pt(i))),
    ))
    // 进度弧：seg 为 0 时跳过，否则 curve 收不到点会报错
    if seg > 0 {
      place(top + left, curve(
        stroke: 5pt + rgb("#2F5BEA"),
        curve.move(pt(0)),
        ..range(1, seg + 1).map(i => curve.line(pt(i))),
      ))
    }
    place(center + horizon, text(weight: "bold", size: 14pt)[#pct%])
  })
}
```

### 11.4 环形进度的四个坑（全部实测踩过）

| 现象 | 根因 | 修法 |
|---|---|---|
| **圆环不闭合、成水滴形** | `curve(...)` 第一条指令是 `curve.line(p)`，起点默认 (0,0)，于是从左上角拉一条线到 12 点 | 必须 `curve.move(pt(0))` 显式指定起点，再 `range(1, ...)` 从第 2 点开始 line |
| **蓝弧比灰环偏右上** | 同上的起点问题，两条曲线各自被 (0,0) 拉歪 | 同上，两条都加 `curve.move` |
| **圆环跑到文字右下方** | `place(top+left)` 原点在 box 左上 (0,0)，`place(center+horizon)` 原点在中心，混用就错位 | 圆环用 `place(top+left)` 且坐标统一加 `r + stroke/2` 偏移；文字单独用 `place(center+horizon)` |
| **`expected integer, found float`** | `calc.round()` 返回 float，`range()` 只要整数 | `int(calc.round(pct / 100.0 * float(steps)))` |

另外：`seg == 0` 时要 `if seg > 0` 跳过进度弧，否则 `curve` 一个点都收不到，编译报错。

### 11.5 序号徽章标题

```typst
#let numtitle(n, t, fill: rgb("#2F5BEA")) = block(width: 100%)[
  #grid(columns: (auto, 1fr), gutter: 8pt, align: horizon,
    box(width: 22pt, height: 22pt, radius: 50%, fill: fill,
      align(center + horizon, text(fill: white, weight: "bold", size: 10pt)[#n])),
    text(weight: "bold", size: 12.5pt, fill: rgb("#1F2933"))[#t],
  )
]
```

`align: horizon` 让圆点和标题**基线对齐**；漏了会变成顶部对齐，圆点看起来偏高。

### 11.6 排版落地要点

- **样张用 `#set page(height: auto)`**：七类组件 A4 装不下会断成两页，自适应高度合成一页，`210×316.9mm`。
- **纵向间距别用 `#v()` 堆**：`#v(16pt)` 一多就跨页，实际用 7pt 级足够。
- **未封装成组件的原因**：`circle`/`ellipse`/`polygon`/`path`/`curve` 的参数（半径、顶点坐标）无法用「名称|数值」两列表达，强行封装会让 AI 学习成本超过收益。需要时走 `extra_typst` 逃生口。

## 12. wrap / vertical 组件（2026-11-22 新增）

把 meander（环绕）和 basho（竖排）包成了 fenced div 组件，AI 不用写 Typst 也能用。

### 12.1 语法

```markdown
::: wrap
left-top|45mm|38mm
这里是要环绕的正文。首行声明障碍框，其余行都是内容。
:::

::: vertical3
竖排正文。数字 = 列数，从右往左排。
:::
```

| 组件 | 参数 | 说明 |
|---|---|---|
| `wrap` | 首行 `位置\|宽\|高` | 位置取 `left-top`/`right-top`/`left-bottom`/`right-bottom`，宽高必须带单位 |
| `vertical` / `vertical2` / `vertical3` | 数字 = 列数 | 也可写 `cols=3 size=10pt gap=3pt` |

### 12.2 ★ 环绕必须不能包 block

**这是本节最重要的一条。**

```typst
// ❌ 这样写，环绕完全不生效，文字只是被挤到右边
#let wrap(body, obstacles: ()) = block(width: 100%, {
  meander.reflow({ ... })
})

// ✅ 直接返回 reflow 的结果
#let wrap(body, obstacles: ()) = {
  meander.reflow({
    import meander: *
    placed(top + left, box(width: 45mm, height: 38mm))
    container()
    content(body)
  })
}
```

原因：`meander.reflow` 需要在外层容器的**布局上下文**里计算避让轮廓。
套一层 `block(width:)` 之后，reflow 拿到的可用宽度信息被打断，`container()` 退化成
「整块让开」，于是文字全被推到障碍物右边，看起来像「环绕失效」。

### 12.3 数字后缀的组件名要特殊处理

`::: vertical3` 里的 `vertical3` 整体是**一个类名**，不会被拆成 `vertical` + `3`。
所以 `_div` 的分支要额外判断：

```python
elif name in ("vertical", "tate") or (
        name.startswith("vertical") and name[8:].isdigit()):
    _n = name[8:] if name.startswith("vertical") and name[8:].isdigit() else ""
    self.o.append(self._vertical(inner, cls, kvs, n=_n) + "\n\n")
```

不这么写的话，`::: vertical3` 会掉进「未知组件」分支，只留文字、丢掉竖排。

### 12.4 告警（已接入统一 warnings 通道）

| 情况 | 告警 |
|---|---|
| wrap 没写障碍框 | `wrap 里没有写障碍框，首行要写「位置\|宽\|高」` |
| 位置名写错 | `只支持 left-top/right-top/…，已按 left-top` |
| 宽高缺单位 | `缺少单位（mm/cm/pt），已按 mm 处理` |
| wrap 只有障碍没正文 | `wrap 里没有正文` |
| vertical 列数越界 | `只支持 1-8，已按 1 列处理` |
| vertical 没内容 | `vertical 里没有内容` |

### 12.5 验证

真实工具调用产出（`warnings: null`）：

- `::: wrap` + `right-top|40mm|32mm` → 文字绕右上角方块，左侧满宽排布
- `::: vertical3` → 三列竖排，从右往左，中文标点落字框右上
- 同期回归：progress / ring 均正常，无警告

### 12.6 已知限制

- 环绕的障碍框是**无色方块**（`fill: luma(235)` 占位）。要放真实图片，走 `extra_typst` 或
  后续加 `::: wrapimg`（把首行换成图片路径）
- `vertical` 的竖排标点是 basho 内置的日文禁则，中文句号「。」会显示为「︒」样式，
  视觉可接受但严格中文排版规范下不完全一致
- 长段竖排会撑高页面，建议配合 `pagebreak` 分页

## 13. 幻灯片版式 slide（2026-11-22 新增）

##14.学科图形体系（2026-11-26）

###三层结构

1. **`::: draw`**：正文里嵌任意 Typst代码的逃生口。md2typst里 `_draw`分支解析 fenced code并原样输出，所以第三方包的能力都能用。

- `ball(pos, r, col, lab:)`：单个渐变球，自己搭构型用

数据表：`_shape`（7种构型的2D投影坐标）、`_mol`（14个分子）、`_ecol2` / `_erad2` / `_etxt2`（元素色 /半径 /字色，**拆成三个扁平字典**，嵌套 `.at()`会返回函数）。

3. **内嵌第三方包**（`gen_package.py`的 `_PREVIEW`）：18个 preview包 +2个 local包，解包到运行时的 `typst-packages/`，`::: draw`里用 `#import "@preview/xxx:ver"`调用。

###为什么分子模型不用 WASM包

生态里的 `molfig` + `maquette`能做真3D球棍 /空间填充，但 +850KB、球面低多边形、键有竖条纹。cetz自绘只 +7.4KB且矢量清晰。详见踩坑记录二十六。

##15.运行时解包（2026-11-26重写）

###产物单一真源

`gen_package.py`只写 `dev_package/ai_pdf/ai_pdf.js`。**仓库里的 `dist/ai_pdf.js`要手动 cp**，否则推上去的是上一版（踩坑记录二十八）。

### `ensure()`流程

1.读 `.ver`，与包内 `VER`（8个核心文件的 hash）比
2.不一致 →写核心文件 → `unpackLibs()` →写 `.ver`
3. `.gnpver`单独管 `gen_package.py` + `pdfxray.py`（只改这两个时 `.ver`不变，需要独立戳）
4. `ensureTypst()`：查 `/root/bin/typst`，没有就从包里拷或下载
5. `ready = true`（仅进程内缓存）

### `unpackLibs()`当前实现

```js
await Tools.Files.writeBinary(tgz, LIBS_B64); //直写 gzip字节，不落 base64文本
await sh('tar xzf ' + tgz + ' -C ' + PKG_DIR);
```

-内嵌格式：**tar** + gzip + base64。打包端用 tarfile，成员排序 +mtime0 +uid/gid0 +uname空，gzip mtime0，保证两次构建同 hash
-为什么不是 JSON字典：Python逐文件写267次在 FUSE上要18秒
-为什么用 `writeBinary`：`write`写1.66MB base64要6158ms，`writeBinary`只要170ms（差36倍）

##16. `wrap` vs `wrapStatic`（2026-11-26）

`wrap(fn)` = `ensure()` +调用，走完整链路。
`wrapStatic(fn)` =只 `complete()`，不碰 `ensure()`。

目前只有 `list_pdf_themes`走 `wrapStatic`，因为它是硬编码数组、零 IO。其余23个工具都会先跑 `ensure()`。

**测出来的教训**：包装器里的“公共前置”要按工具类型分开。一个 `ensure()`把所有工具绑在一起，静态工具也得陪跑18秒。
