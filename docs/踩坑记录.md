#踩坑记录

开发 ai_pdf v2（Typst引擎）期间踩到的坑，按"值得记住"排序。**每条都经过实测验证**，不是推测。

- --

## A. Typst引擎层

### A1. `#let pagebreak() = pagebreak()`自递归 →爆栈

**现象**
```
error: maximum function call depth exceeded
┌─ xx.typ:448:19
448 │ #let pagebreak() = pagebreak()
```
只要文档里出现 `::: toc`就整份编译失败。

**根因**：本意是"包一层"，但 `pagebreak`在右侧解析到**自己**，形成无限递归。Typst的 `#let`不区分"内置名"与"新名"。

**修法**：删掉这行。`pagebreak()`是 Typst内置函数，转换器输出 `#pagebreak()`时直接命中内置实现，**不需要也不应该重新定义**。

**教训**：给内置函数起同名封装，等于自杀。要封装就换名（如 `pb()`）。

- --

### A2. `#block`默认 `above:1.2em` →标题下划线飞出60px

**现象**：二级标题的文字和它的下划线之间空了约40–60px，看起来像"标题和一条分隔线"，而非"带下划线的标题"。

**根因**：h2的 show规则里嵌套了两个 `#block`（灰线、蓝短线）。Typst的 `block`默认 `above: auto`，会取全局 `block.spacing`（默认 **1.2em**）。两个 block各加约13pt，加上 `#v(5pt)`，凑出30pt+空隙。

**修法**（两步都必须）：
1.全局 `#set block(spacing:0pt)` ——让 `#v()`、`above`、`below`成为唯一间距来源
2. h2改用 **stroke画线**，不用额外 block：
```typst
#block(width:100%, stroke: (bottom:0.6pt + lc), inset: (bottom:4pt))[
 #text(...)[#it.body]
]
#v(0.5pt)
#block(width:20mm, height:1.6pt, fill: accent, radius:0.8pt)
```

**验证方式**：改完渲染 PNG，用肉眼量文字底到下划线的距离，不是看"有没有报错"。

- --

### A3. `text()`没有 `leading`参数

**现象**
```
error: unexpected argument: leading
474 │ #block(width:126mm, text(size:12.5pt, fill: rgb("#5B6672"), leading:0.85em)[副标题])
```
**根因**：把 `par(leading:)`误当成 `text()`的参数。Typst里行距属于 **段落**，不属于文本。

**修法**：要么用 `#set par(leading: ..)`作用域，要么直接去掉。**在内容块里连续写两个 `#set`还会触发"already in code mode"**（`#`在代码模式里非法），所以最省事的是不覆盖、用主题默认。

- --

### A4. `box()`没有 `align`参数

**现象**：`#box(... align: center + horizon)[...]` → `unexpected argument: align`。

**根因**：`align`是 `block`/`grid.cell`/`place`的参数，不是 `box`的。

**修法**：用 `place`叠放：
```typst
#block(width:15pt, height:15pt, radius:999pt, fill: accent,
 place(center + horizon, text(...)[#(i+1)]))
```

- --

### A5. `enum.item.where(level:1)`字段不存在

**现象**：`error: element 'item' does not have field 'level'`。

**根因**：`enum.item`是枚举项元素，没有 `level`字段（`heading`、`list`才有层级概念）。

**修法**：删掉该 show规则。有序列表编号直接用 `#set enum(numbering: "1.")`。

- --

### A6. `margin:22mm20mm`解析失败

**现象**：`error: invalid number suffix: mm22mm`。

**根因**：参数拼成 `margin:24mm22mm`——没有分隔符，Typst当成一个数。

**修法**：在 `margin_typst()`里用正则**按单位切分**，再拼成命名边距：
```python
parts = re.findall(r'[0-9]+(?:\.[0-9]+)?(?:mm|cm|in|pt|em|%)', str(spec)) or [unit(spec)]
# → (top:22mm, right:20mm, bottom:22mm, left:20mm)
```
CSS式1/2/3/4值展开也在这里做。

## B.转换器层（md2typst）

### B1. pandoc **不认** `::: callout note说明`

**实测**（`-t json`）：
```json
{"t":"Para","c":[{"t":"Str","c":":::"},{"t":"Space"},{"t":"Str","c":"callout"} ...]}
```
整块退化成普通段落，`:::`原样进了 PDF。

**根因**：fenced div的属性行**只接受英文标识符**。`::: callout note说明`里的中文破坏了语法；只有 `::: {.callout .warn}`这种标准写法才被识别。

**修法**：自己写预处理器，把简体语法翻译成标准形式：
```
::: callout warn交付瓶颈
→ ::: {.callout .warn data-title="交付瓶颈"}
```
要点：
- 第一个词是组件名 → `.name`
- 已知变体（note/info/success/warn/danger/quote/primary/soft/neutral）→ `.variant`
- 变体若与标题粘连（`warn交付瓶颈`）→ **按前缀拆开**，余下当 `data-title`
- 值含中文/空格 →加引号

**通用教训**：任何"看起来像语法糖"的写法，先用 pandoc `-t json`确认 AST长什么样，再决定要不要自己预处理。

- --

### B2.手写 pandoc native解析器 →结构全错

**现象**：`convert()`返回空字符串，或把 `Header1 (...)`的参数合并错。

**根因**：pandoc的 `-t native`是 Haskell `show`格式，构造器后跟多个参数、数组/元组/render混排、字符串里还有十进制字符引用（`\27573`）。手写递归下降时 `_parse_seq`把"构造器+多个参数"的边界吃掉了。

**修法**：**改用 `-t json`**。官方稳定格式，`json.loads`一行搞定，AST是 `{"t":"Para","c":[...]}`的结构化对象。

**教训**：解析第三方工具的中间格式，永远优先选它的 JSON模式。手写解析器是纯亏损。

- --

### B3.组件 div的 class是 `cards2`，代码只认 `cards`

**现象**：`::: cards2`的四张卡片垂直堆成一列，`cols`完全没生效。

**根因**：预处理器把 `cards2`变成 `.cards2`，而 `_div()`里判断的是 `name == "cards"` →不匹配 →落到 else分支（原样渲染 body，所以标题和正文都在，但没有网格）。

**修法**：
```python
elif name.startswith("cards"):
 cols = name[5:] if name[5:].isdigit() else None
 self.o.append(self._cards(inner, cls, kvs, cols) + "\n\n")
```

**教训**：带参数的组件用"名字+后缀"传参（`cards2`），就要在接受端做前缀匹配，不能等值比较。

- --

### B4.标题 `##一、`无空格 →不被识别

**现象**：`##一、关键指标`原样印在 PDF上，`##`成了正文。

**根因**：ATX heading要求 `#`后有空格。中文场景下写 `##一、`很自然，但 pandoc不认。

**修法**：预处理补空格：
```python
md = re.sub(r'(?m)^(#{1,6})([^\s#])', lambda m: m.group(1) + ' ' + m.group(2), md)
```
正则要求 `#`后**非空白且非#**，所以 `####`这种纯符号行不会被误改。

- --

### B5.任务清单：pandoc的 `task_lists`不生效 →圆点+方框双标记

**现象**：`- [x]完成数据核对`渲染成 `• [x]完成数据核对`——既保留了 `[x]`原文，又多了列表圆点。

**排查过程**（三次尝试）：
1.开 `+task_lists`扩展 →无效（`- [x]完成`中 `]`后缺空格，pandoc不认为它是 task item）
2.改 `- [x]内容`（补空格）→仍然无效
3.用 `TASK_MARKS`检测首字符隐藏圆点 →没触发，因为 pandoc根本没产出 ☐/☒

**最终修法**：**绕开 pandoc**，预处理阶段直接转 Unicode方框：
```python
md = md.replace("- [x]", "- " + chr(0x2612) + " ") # ☒
md = md.replace("- [X]", "- " + chr(0x2612) + " ")
md = md.replace("- [ ]", "- " + chr(0x2610) + " ") # ☐
```
然后列表渲染器检测首字符：
```python
if txt[:1] in TASK_MARKS: # ☐ ☒ ☑
 self.o.append(' #block(inset: (left:1.2em, y:2.5pt))[%s]\n' % txt)
else:
 self.o.append('%s %s\n' % (marker, txt))
```

**注意两个细节**：
- 替换**不能要求尾随空格**（`- [x] `），否则 `- [x]完成`不命中——这是第二遍失败的原因
- `#block` **必须给纵向 inset**（`y:2.5pt`），否则在 `block(spacing:0pt)`下多行会贴在一起变成一行

### B6.列表缩进：`-`后没空格 →整段挤成一行

**现象**：`-现场工程师缺口约12人-备件周转从6天升至9天`全在一行。

**根因**：Markdown列表标记后必须有一个空格。工具链（写入环节）把行首空格压掉了。

**修法**：多步正则补齐（**注意保护小数**）：
```python
S2 = re.sub(r'(?m)^-(\S)', r'- \1', S1)
S3 = re.sub(r'(?m)^( +)-(\S)', r'\1- \2', S2)
S4 = re.sub(r'(?m)^(\d+)\.(?!\d)[ \t]*', r'\1. ', S3) # (?!\d)保护 "1.84亿"
S5 = re.sub(r'(?m)^>(\S)', r'> \1', S4)
```
`(?!\d)`是关键：`1.84亿`不能被当成有序列表。

- --

### B7. `blockquote`未定义

**现象**：`error: unknown variable: blockquote`。

**根因**：转换器输出 `#blockquote[...]`（沿用 HTML思维），但 Typst里引用块是 `quote(block: true)`。

**修法**：在 theme里加别名：
```typst
#let blockquote(body) = quote(block: true)[#body]
```

## C.打包与运行时

### C1.修改 core.py后运行时仍是旧版本

**现象**：改完代码、重新构建、重新安装，行为没变。

**根因**：运行时目录 `/sdcard/Download/.ai_pdf_runtime/core.py` **已存在就不覆盖**，于是跑的是旧代码。

**修法**：**按内容哈希做版本号**。构建时把三个源文件的 sha256前16位写进 `VER`，运行时比对 `.ver`文件，不符才覆盖。

**教训**：任何"首次解包到本地"的设计，都必须带版本校验，否则改动永远不生效。这是"两份实现"的典型形态。

- --

### C2. `/sdcard`是 `noexec` →二进制不能执行

**现象**：`Permission denied`，即使 `chmod +x`。

**修法**：二进制放 `/root/bin/`（Linux可执行区），`/sdcard`只放数据。包内 `ensureTypst()`三级兜底：现有可执行 →本地复制 →GitHub下载。

- --

### C3. `err()`用 `sys.exit(1)` →JS层拿不到错误详情

**现象**：工具返回空 `Step error:`，看不到任何错误文本。

**根因**：`hiddenExec`对非零退出码抛异常，JS的 `catch`里取不到 `output`，只剩一句"Command exited with code1"。

**修法**：**错误也用 exit(0)返回**，把 `success:false` + `error` + `error_type` + `hint`放进 JSON。这样 JS永远能解析。

**教训**：跨进程边界时，"退出码表达失败"会把 payload一起丢掉。用数据表达失败。

- --

### C4.错误只有原文 →加 `error_type` + `hint`

**修法**：`classify(msg)`按 stderr特征分类：

| error_type |触发特征 | hint |
|---|---|---|
| `internal_recursion` | `maximum function call depth` |主题内部递归（工具bug），反馈维护者 |
| `undefined_symbol` | `unknown variable` |组件名/函数不存在，查 `extra_typst` |
| `bad_unit` | `invalid number suffix` |边距用 mm、字号用 pt、行距用 em |
| `bad_argument` | `unexpected argument` |多半是 `extra_typst`给了不支持的键 |
| `syntax` | `unclosed delimiter` / `expected` |删掉 `extra_typst`重试 |
| `missing_resource` | `not found` |图片用绝对路径、字体换 Noto |
| `markdown` | `pandoc` |检查未闭合的 `:::`或代码块 |
| `engine` | `typst binary` |先跑 `pdf_selfcheck` |

## D.环境/工具链

### D1.48 MB二进制无法内嵌 JS

48.6 MB → gzip24 MB → base64约32 MB。Operit沙盒包塞这个体积不现实。
**结论**：二进制走运行时获取，只内嵌三个源文件（约56 KB）。

### D2. `/sdcard`与 Linux侧 `/tmp`不互通

**现象**：脚本写 `/sdcard/.../x.py`后 `python3 /tmp/x.py`报 No such file。

**修法**：源文件与临时文件都放 `/sdcard/Download/...`，两端都能访问。只有需要"可执行"的东西才放 `/root`。

### D3.工具层会压缩连续空格（写文件时）

**现象**：写 Python脚本时，`def f():`内部的多级缩进被压成1个空格，导致 `if`/`for`的空 body → `IndentationError`。

**这是本工程最大的时间黑洞**（约一半的调试时间花在"文件被写坏"上）。

**规避手段**（按可靠性排序）：
1. **纯扁平 Python**：只用顶层语句 +推导式，不写 `def`里的嵌套（`re.sub`链式调用最可靠）
2. **行首级别标记**：每行写 `0§code`、`1§code`，再用生成脚本还原缩进
3. **bash脚本**：shell不关心缩进，`for ... do ... done`安全
4. **`chr(32)*n`拼接**：需要精确缩进时，用 `S=chr(32); I4=S*4`构造

**同时**：连续写 `"..."`相邻的引号会被替换成弯引号，所以 Python源码里要避免 `""`相邻，用 `chr(34)`代替。

### D4. shell里 `'...'2>&1`缺空格 →参数被污染

**现象**：`bad json args: Extra data: line1 column109 (char108)`，字符位置正好是 JSON末尾。

**根因**：`python3 core.py build '{"out":"..."}'2>&1`写法里，引号与 `2`之间**必须有空格**。空格被吃掉后，shell把它解析成 `'...'2`（字符串+数字拼接），`2`被当成JSON的一部分。

**修法**：重定向单独写、前面留空格；或干脆不重定向，输出到文件。

**教训**：这类错误看起来像"参数解析bug"，实际是自己的命令行拼错。**看报错里的字符位置**能立刻定位（char108 = JSON长度）。

### D5.验收要靠图片，不能靠返回值

多次出现"返回 success:true但排版是坏的"：
- h2下划线飞出60px
- 卡片网格单列
- 任务清单行距为0
- 列表挤成一行

**结论**：`make_pdf`返回的 `success/pages/bytes`只能证明"产出文件"，**不能证明"排版正确"**。所以工具里内置了 `render_pdf_preview`，且开发流程固定为：生成 →渲染 → **看图** →改 →再看。

## Mermaid 图的坑（2026-11-22）

### 1. mmdc 装不了

`@mermaid-js/mermaid-cli` 能 `npm install -g` 装上，`/usr/bin/mmdc` 也存在，但**一运行就崩**：

```
TROUBLESHOOTING: https://pptr.dev/troubleshooting
at ChildProcess.onClose (@puppeteer/browsers/lib/launch.js:346:24)
```

根因：mmdc 依赖 Puppeteer 下载 Chromium。这台设备访问不了 Google CDN，且内存只剩 245MB，起不了浏览器。**这条路直接排除。**

### 2. mermaid-py 渲染不出中文

`pip install mermaid-py` 成功，`Mermaid(code).to_svg()` 也能跑，流程图/时序图都能生成 SVG。

但**中文标签全丢**。检查 SVG：

```
text nodes 0          ← 一个 <text> 都没有
font-family: trebuchet ms
```

它用 Python 重画 SVG，文字全靠路径填充，而 `trebuchet ms` 没有中文字形，绘制出来是空白。**结构对、标签空**，等于没用。

### 3. graphviz 也没装

`dot` 二进制、`graphviz` / `pydot` / `pygraphviz` 全部缺失。且 apt 装 graphviz 会拉一堆依赖，在这台设备上风险高。

### 4. 结论：用 Typst 原生画

最后选了最笨但最可靠的路：**把 Mermaid 语义翻译成 Typst 绘图代码**，直接用 `box` + `stack` + `grid` + `line`。

好处：
- 零外部依赖，不装任何东西
- 中文和字体由 Typst 原生处理，不可能丢
- 配色跟主题联动（能用 cfg.accent）
- 输出是矢量，无限缩放

实测可用的三块基石：

```typst
// 圆角节点
#let nd(b) = box(inset: (x: 10pt, y: 5pt), radius: 3pt,
                 fill: rgb("#EEF3FF"), stroke: 0.8pt + rgb("#2F5BEA"), b)

// 垂直堆叠
#stack(dir: ttb, spacing: 8pt, nd[开始], nd[结束])

// 真斜线（比 ↓ 字符专业）
#line(angle: 55deg, length: 42pt, stroke: 0.8pt + rgb("#1F7A5A"))

// 分支两列
#grid(columns: (1fr, 1fr), column-gutter: 26pt, 左, 右)
```

注意：`#let arrow(c: ...)` 这种带默认参数的函数，调用时**必须用命名参数** `#arrow(c: rgb(...))`，不能省 `c:`，否则报 `unexpected argument`。

## fenced div 内 heading 不生效（2026-11-22）

### 现象

`::: cards3` 只渲染出第一张卡，`::: compare` 右栏全空，`::: rating` 四行挤成两行。

### 根因

pandoc 的 fenced div 里，**heading 后面紧跟内容时，后续 `###` 会被当成同一段的续行**（SoftBreak 文本），不再解析成 Header。

实测 AST：

```json
{"t":"Para","c":[
  {"Str":"纯"},{"Space"},{"Str":"Markdown。"},
  {"SoftBreak"},
  {"Str":"###"},{"Space"},{"Str":"转换"},   ← 变成普通文本了
  ...
]}
```

于是 `_grouped()` 只切出 1 组，`_cards` 只出 1 张，`_compare` 取不到第 2 组。

### 修法

`preprocess()` 末尾加一遍扫描：**在 fenced div 内部，给每行 heading 前补一个空行**。

```python
_l2 = res.split("\n")
_fin = []
_inside = False
for _ln in _l2:
    _st = _ln.strip()
    _is_fence = _st.startswith(":::")
    if (not _is_fence) and _inside and _re.match(r"^#{1,6}[ ]", _st):
        if _fin and _fin[-1].strip():
            _fin.append("")
    _fin.append(_ln)
    if _is_fence:
        _inside = not _inside
```

**顺序注意**：必须先判断 heading 再 append 当前行，否则空行会插到自己后面。

## 列表间距与编号（2026-11-22）

### 三个坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 有序列表顶在无序列表下面 | `- item` 裸行在 `#set block(spacing:0pt)` 下无纵向间距 | 整块包 `#block(above: 7pt, below: 7pt)` |
| 任务清单缩进错乱 | `☒` 行走 `#block(inset: left:1.2em)` 但普通行没走同一容器 | 每行统一 `#block(inset: (left: 1.3em * depth))` |
| 有序列表编号全是「1.」 | `+ item` 在独立 `#block` 内各自开列表，Typst 每次都从 1 计 | **手动编号** `"%d." % _seq`，不用 `+` |

### `+` 不能用来做有序列表的原因

Typst 的 `+` 是「自动编号列表项」，编号由**所在 list 上下文**决定。一旦每行被包进独立 `#block`，每行就是一个新上下文，编号永远从 1 开始。

## 重写方法时 end 指针错位，删掉 7 个方法（2026-11-22）

### 事故

用 `lines[start:end] = NEW` 替换 `_list` 方法时，`end` 定位到 `def _table`，但当时 `_table` **不在** `_list` 后面（中间还有 7 个方法），结果 `_chart` / `_timeline` / `_steps` / `_numbered` / `_pairs` / `_badges` / `_fontspec` 全被覆盖删除。

文件从 29892 字节掉到 25657 字节 —— **体积骤降就是信号**，但我先打包了才发现。

### 恢复

已安装的 `ai_pdf.js` 里 base64 存着源码，直接抽出来：

import re, base64

## 工具写文件会压缩连续空格（2026-11-22 反复踩）

用 `create_file` / `apply_file` 写 Python 时，**行首缩进会被压成 1 个空格或直接丢失**，`return 0` 会变成 `return0`。

已经因此产生过：
- `_fin.append(_ln)` 缩进丢失，整段逻辑变成死代码
- `for txt, no_mark, depth in rows:` 缩进丢失，语法报错
- `self.o.append(...)` 缩进丢失

**可靠做法**：

```python
S16 = chr(32) * 16
lines.append(S16 + '代码')
```

或在终端用 heredoc（`cat > x.py << 'EOF'`）—— 实测 heredoc **不会**压缩缩进。

## 静默失败：输入写错但返回 success（2026-11-22 集中修）

**这几个坑的共同点：工具没报错，AI 以为成了。**

| 写错什么 | 现象 | 修法 |
|---|---|---|
| `::: oval`（不存在的组件） | 内容还在，外框消失，无提示 | `_div` 的 else 分支记 WARNINGS |
| `::: chart` 忘了闭合 | 后面全部内容被当成同一块 | preprocess 末尾判 `_inside` 告警 |
| `::: progress 名称\|值` 写在同一行 | 整行原样印进 PDF（`:::` 后必须有空格才被 pandoc 识别） | 未闭合分支会捕获到 |
| 代码块语言拼错 | 静默当纯文本 | KNOWN_CODE_LANGS 白名单告警 |

**告警怎么回给 AI**：`md2typst.convert_checked()` 返回 `(源码, warnings)`，core.py 把它放进 JSON。实测：

```json
{"success": true, "pages": 1,
 "warnings": ["fenced div 未闭合…", "未知组件 ::: oval…"]}
```

**为什么 success 不改 false**：文件确实生成了，卡死会让 AI 拿不到任何产物。用 warnings 另开一条通道，既保留产物又暴露问题。

**验证方式**：故意写错的 md 进去，检查 warnings 非空。不能拿 success 当证据。

## 环形进度：圆环不闭合 / 蓝弧偏位

| 现象 | 根因 | 修法 |
|---|---|---|
| 圆环变成水滴形，顶部有缺口 | curve 的第一条指令是 line，起点默认 (0,0)，从左上拉一条线到 12 点 | 必须 `curve.move(pt(0))`，再 `range(1, steps+1)` |
| 蓝弧比灰环偏右上 | 同上，两条曲线各自被 (0,0) 拉歪 | 两条都加 `curve.move` |
| seg=0 时编译报错 | curve 一个点都收不到 | `if seg > 0 { }` 跳过 |
| 环跑到文字右下 | place 原点不同 | 圆环 `place(top + left)` + 坐标加 `d/2` 偏移 |

**教训**：curve 不是「点列表自动连线」，它需要显式起点。这和 SVG path 的 `M` 一样。

## 输入校验清单（2026-11-22 全量补齐）

原则：**能在输入期判定的问题，就在输入期说出来，且保留产物。**
`success` 保持 true，问题走 `warnings` 数组。共 14 类。

### A. 组件层（`md2typst._div`）

| 触发条件 | 告警文案要点 |
|---|---|
| 组件名不在支持列表 | `未知组件 ::: xxx —— 已按普通段落渲染，格式丢失` |
| `:::` 没闭合 | `fenced div 未闭合：文末还开着 :::` |
| 组件内没有数据行 | `组件 ::: xxx 里没有任何数据行，渲染出来会是空块` |
| 卡片列数越界 | `卡片列数写了 99，只支持 1-6，已按 2 列处理` |
| compare 少于 2 组 | `对比栏只有 1 组，需要 2 组（每组以 ### 标题开头）` |

### B. 数据层

| 触发条件 | 告警文案要点 |
|---|---|
| 数值字段不是数字 | `数值字段写成了 abc，不是数字，已按 0 处理` |
| 表格行有空格子 | `表格第 2 行有 2 个空单元格（位置 2,3），源 Markdown 很可能少写了 \|` |

**表格这条要特别说明**：pandoc 会把缺的单元格补成空，所以「行长度 != 列数」永远不成立。
真正的信号是**中间出现空单元格**。第一版判长度，抓不到；改成判空格才准。

### C. 内容层

| 触发条件 | 告警文案要点 |
|---|---|
| 不支持的 LaTeX 命令 | `公式里有不支持的 LaTeX 命令 badcommand，已整条改为纯文本` |
| Mermaid 渲染异常 | `Mermaid 渲染失败（已回退成代码块）` |
| 代码块语言未知 | `代码块语言 xxx 无高亮规则，按纯文本渲染` |
| 列表嵌套 | `嵌套层级会被压平（已知限制，不影响内容）` |

### D. 参数层（`core.py`）

| 触发条件 | 告警文案要点 |
|---|---|
| theme 不存在 | `theme 写了 xxx，不存在，已用 report。可选：certificate/editorial/...` |
| palette 不存在 | `palette 写了 彩虹，不存在，已用 blue。可选：blue/clay/forest/gold/ink/plum` |
| page_size 不存在 | `page_size 写了 a99，不存在，已用 a4。可选：a3/a4/a5/b5/letter` |

告警会带上**可选值全集**，AI 不用再猜。

## 公式兜底：这是唯一会让整份 PDF 归零的坑

`\badcommand{x}` 这种不存在的 LaTeX 命令，texmath 的处理是「去掉反斜杠、原样留着」：

```
\badcommand{x}  ->  badcommand{x}
```

这串东西进 Typst 数学环境，编译直接失败 **`unknown variable: badcommand`**，
整个 PDF **一个字节都产不出来**。这是所有错误里后果最严重的一种。

### 检测判据（第一版判错了）

- ❌ 判 `\\[A-Za-z]`（结果里找反斜杠）→ 永远匹配不到，因为反斜杠已被 texmath 去掉
- ✅ 判「裸多字母标识符紧跟 `(` 或 `{`，且不在 `TYPST_MATH_FUNCS` 白名单」

白名单含 frac/sqrt/root/sum/int/lim/vec/mat/abs/hat/text 等 100+ 个 Typst 内置数学函数。

### 兜底行为

命中后整条公式降级为普通斜体文字，并**保留原文命令名**：

```
\badcommand{x}  ->  badcommandx（斜体文字）
```

让人一眼看出写错的是哪个命令，而不是只剩一个 `x`。

### 验证

正常公式 `$E=mc^2$`、`$\frac{a}{b}$`、`$\sqrt[3]{x}$` 全部不受影响，实测无回归。

## 加告警时踩的两个自己的坑

**① 白名单长字符串断行写错**
用 `'...mat",\n' + '    "abs"...'` 拼接时漏了引号闭合，造出 `"mat",` 后面直接换行接 `"abs"` 的语法错误。
改成 `WORDS.split()` 逐词 append，不再手写长字符串。

**② 拿 `len()` 当字节数校验**
`gen_package.py` 打印的 `163012 bytes` 是字符数，实际磁盘 163253 字节。
中文 UTF-8 一字符占 3 字节。校验产物必须用 `os.path.getsize` / `wc -c`。

## 又补两类：图片路径与字体名

| 写错什么 | 后果 | 修法 |
|---|---|---|
| 图片路径不存在 | **整份 PDF 编译失败**（error: file not found） | 转换期 os.path.exists 预检，降级为占位框 + 告警 |
| font_body 字体名写错 | Typst 只打 warning，静默回落默认字体，**不报错也不进 warnings** | 用 typst fonts 拿真实列表校验，附拼写建议 |

字体校验的实现要点：

- 用 `/root/bin/typst fonts --font-path <每个字体目录>`，这是实际渲染的那个二进制，不会漏也不会多
- 结果缓存在 `_FONT_CACHE`，不要每次 build 都扫 388MB 字体库
- 拼写建议用前 4 字符做模糊匹配：`Cinzell` → 提示 `Cinzel`
- 拿不到字体列表时直接 return，**不误报**

累计 16 类校验，全部有真实注入测试通过。

## 二十、参数死在了 JS 层（font_dir 事件）

**现象**：`font_dir` 传不存在的目录，`warnings` 里没有告警。上一轮已经在 core.py 的 `font_paths()` 里加了
`PARAM_WARN.append(...)`，代码明明白白写着，却从未触发。

**根因不在 core，在 JS**：`gen_package.py` 的 `make_pdf` 用一份**手写白名单**决定哪些参数传给后端：

```js
['theme','palette','page_size','margin','base_size','leading',
 'font_body','font_head','header_text','watermark','title',
 'subtitle','kicker','cover_meta','cover_cards','extra_typst']
.forEach(function (k) { if (p[k] != null && p[k] !== '') a[k] = p[k]; });
```

`font_dir` 在 `PARAMS` 元数据里声明了（工具描述里也大方展示），但**不在这份白名单里**，
所以它永远到不了后端。后端那段告警逻辑等于死代码。

**为什么难以发现**：工具描述里能看到 `font_dir` 参数、也能正常传进去、后端也不报错、
返回 `success: true`。整条链路每一环都“看起来正常”，只有效果不存在。

**修法**：把白名单改成黑名单式——只排除已做特殊映射的参数，其余一律透传：

```js
const SPECIAL = ['output_path','content','input_path','input_format'];
Object.keys(p).forEach(function (k) {
  if (SPECIAL.indexOf(k) >= 0) return;
  if (p[k] != null && p[k] !== '') a[k] = p[k];
});
```

这样以后新增参数不会因为忘了改白名单而变成死参数。`cover` / `page_numbers` 的规范化赋值
放在透传之后，仍然覆盖生效。

**教训**：一个参数有三处需要同时成立——① 工具 schema 声明、② JS 层透传到后端、
③ 后端真的读它。只验证其中一环（比如 grep 到后端有代码）不等于参数能用。
**新增参数后必须用真实工具调用验证一次，传一个会触发告警或改变输出的值。**

**审计脚本**：按 `tools.append({` 切块提取声明的参数名，再扫 `async function xxx(p)` 函数体里
`p.xxx` 的出现情况，能自动列出死参数。注意 `p[k]` 动态透传的写法会被误报，需人工确认。

## 二十一、幻灯片版式（slide）踩坑六条

### 1. Typst 0.15 自带 presentation 纸张

以为要手写 `paper: (width: 338.7mm, height: 190.5mm)`，报 `found dictionary`。
实际支持列表里就有 `presentation-16-9` / `presentation-4-3`。
**查错信息里的可选值列表，比猜 API 快。**

### 2. `{ }` 代码块里不能再写 `#`

现象：`#if note [` 报 `the character # is not valid in code`。
根因：函数体 `{ ... }` 内部已经是代码模式，`#` 是内容模式标记。
修法：直接写 `if note != none [`。

### 3. `if <content> [` 不是布尔判断

现象：`#if kicker [` 报 `expected boolean, found content`。
根因：可选参数的值是 `content` 类型（或 `none`），不是布尔。
修法：`if kicker != none [`。**`none` 要用 `!= none` 比较，不能直接当布尔。**

### 4. `leading` 不是 `text()` 的参数

现象：`text(..., leading: 0.95em)` 报 `unexpected argument: leading`。
修法：行距只能用 `set par(leading: ...)`，`text()` 不收。批量正则清掉 7 处。

### 5. lambda 参数名遮住内置函数（最隐蔽）

现象：`slide-stats` 报 `expected function, found content`，指向 `#v(1.5mm)`。
根因：`items.map(((v, l, c)) => ...)` 里的 `v` 遮蔽了 Typst 内置的 `v()` 间距函数，
于是 `#v(1.5mm)` 变成「把 1.5mm 当成参数传给内容对象」。
修法：lambda 参数改名 `(val, lab, col)`。
**不要用 v / h / box / text / grid 这类内置名做变量名。**

### 6. 行内 text 后面的 block 会跑到同一行

现象：大数字下方的彩色短线压在说明文字上。
根因：`#text(...)[#val]` 是行内元素，紧跟的 `#block(...)` 会尝试同行排列。
修法：把文字也用 `#block(width: 100%, text(...))` 包起来，强制成块级。

### 7. `align()[...]` 里 `#if` 分支会产生多余逗号

现象：流程页每个圆点下方多一个 `,`。
根因：`align(center + top)[ #block(...), #if ... [ ... ] ]` 里，
内容块内的逗号被当成内容打印出来。
修法：改用 `align(center + top, stack(dir: ttb, ...))`，用 `stack` 明确堆叠。

### 8. title 自动页眉会压到 slide 色条上

现象：`pdf_lint` 每页报 `text_overflow 上 2.5mm：<title>` + `near_edge`，共 16 条。
根因：`cmd_build` 里 `if title and not header_text` 会自动 `set page(header: ...)`，
而 slide 模式 y margin 是 0，页眉没空间。
修法：加 `and pick_theme(a) != "slide"`。修后 lint errors=0 / warns=0。

### 9. `grid` 不支持 `width` 参数

现象：`grid(..., width: 100%)` 报 `unexpected argument: width`。
修法：外层套 `block(width: 100%, grid(...))`。

### 10. heredoc 写代码两次弄坏引号

现象：`python3 - << PYEOF` 里拼 `\\n\\n` 被展开成真换行，破坏字符串字面量；
另一次 `\"` 直接被吃掉。
修法：**改代码一律用 edit_file（不碰转义），或用 create_file 先写脚本再执行。**
本轮因此白花两轮修语法。
